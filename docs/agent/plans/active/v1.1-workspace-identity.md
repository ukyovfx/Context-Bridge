# Context Bridge V1.1 Workspace Identity Plan

Status: complete

## Goal

Add deterministic project, repository, and workspace identity so Context Bridge-mediated mutations fail closed with `WRONG_WORKSPACE` when the intended registered workspace does not match fresh filesystem and Git evidence.

## Scope

- Manifest V2 for newly generated projects, with read-only V1 compatibility
- Machine-local versioned JSON registry with safe single-writer persistence
- Vendor-neutral remote normalization
- Shared read-only workspace probe
- Pure Workspace Guard
- Output-only bounded discovery
- `registry`, `guard`, and `discover` CLI commands
- Separate CURRENT-STATE integrity, basis validity, and basis freshness
- Unit, integration, and local E2E coverage

## Excluded

Task and AgentSession persistence, worktree creation/removal, cleanup execution, automatic repository migration, Git fetch, agent launching, GUI, MCP, vector databases, Obsidian plugins, AI/model calls, and unrelated repositories.

## Verification gates

1. `go test ./...`
2. `gofmt -l .` returns no files
3. `go vet ./...`
4. Local PowerShell E2E passes
5. Guard and discovery failure paths prove zero repository/registry mutation
6. Staged diff contains only Context Bridge V1.1 changes
7. Private remote identity is verified before push

## Completion evidence

- The deterministic core, registry, shared probe, guard, discovery, Manifest V2, and CURRENT-STATE provenance logic are implemented.
- Unit and integration tests cover remote normalization, registry safety, topology, local evidence, guard failures, identity changes before apply, and provenance freshness.
- The Windows local verification gates passed before the implementation commit.
