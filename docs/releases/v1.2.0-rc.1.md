# Context Bridge v1.2.0-rc.1

Release candidate prepared from the private `main` branch. Hosted GitHub Actions is externally blocked by an account billing/spending-limit failure; this RC is not presented as hosted-CI verified.

## Core

- Portable Project and Repository identity with machine-local Workspace identity.
- Machine-local versioned registry with guarded writes and recovery backup.
- Workspace Guard for canonical path, Git root, git-dir, git-common-dir, remote, and branch identity.
- Bounded, read-only discovery with explicit terminal states and reparse-point safety.
- Manifest V2 generated-file provenance.
- Separate `CURRENT-STATE` content integrity, basis validity, and freshness evidence.

## V1.2

- Automatic project and canonical-workspace resolution for routine handoff.
- Deterministic, read-only handoff with task intent and verification contract resolution.
- Codex, Claude Code, and Cursor instruction/environment diagnostics.
- Instruction provenance, warning severity, and actionable diagnostics.
- Explicit plan/apply `adopt`, `upgrade`, and `rebind` operations.
- Concise human summaries and consistent Git trust/probe diagnostics.

## Safety

- Workspace mismatches fail closed.
- No force or skip-guard bypasses.
- Read-only commands and dry-runs remain zero-mutation.
- Credential-bearing remotes and instruction contents are redacted from portable output.
- Git trust failures are reported and never bypassed.

## Known limitations

- External agents can still write outside Context Bridge.
- Context Bridge does not own an agent sandbox or guarantee agent compliance.
- No Task or AgentSession persistence.
- No managed worktrees, cleanup/delete execution, or agent launching.
- No MCP, GUI, daemon, dashboard/TUI, model/API calls, or automatic agent-configuration writes.
- Local unique-work analysis is local evidence and does not prove absence from a remote.
- Hosted CI is externally blocked and remains unverified.
